# Protocol: specialist context and useful policy deliverables

Status: study prepared, participant/data acquisition outstanding. All three launch domains are included: corporate policy, conflict analysis and US/EU legislative analysis. Prepare 50 held-out tasks per domain and two qualified reviewers per domain. Development tasks and fixture tests never count toward that target.

## Questions and conditions

Primary question: does selected institutional/organisational context improve decision relevance without degrading source fidelity? Secondary questions concern retained qualifications, overall task quality, editing effort, total elapsed time and full costs.

Register framing-only comparisons separately from full research/workflow and model comparisons. Framing-only arms use the same source information, model revision, settings, output requirements and declared resource ceilings; only the registered framing differs. A workflow comparison records retrieval/preparation differences explicitly. A different model is a separately labelled model comparison. Neither selected successes nor model substitution may silently change the comparison.

## Acquisition and freeze

Use permissioned cases from real recurring work, with source edition, scope, original bytes/hash, rights and expected review questions. Separate public sources from private organisation guidance. Check overlap at source/document-family and question level; record why a held-out task is independent of development. Do not tune packs on held-out outputs.

Freeze task, source manifest, context version, rubric, model/settings, condition definitions, seeded assignment and budget before execution. Retain exact commits of App, graph/toolkit and canonical evaluator. A local hash establishes consistency, not externally authenticated preregistration. Record actual review/freeze timestamps and participants; never backfill a claim of advance registration.

## Execution and review

Execute through the owning App's confirmed plan, authorization and allowance. This kit does not authorize new providers, production bindings or additional spending. Retain dispatch, failures, uncertain attempts and cancellations. Do not automatically retry uncertain inference or omit a failed condition.

Use canonical blinded output IDs and hide condition labels from reviewers. Reviewers inspect the same permitted evidence and task rubric. Collect source_fidelity, quality, salience and qualifier_preservation on 1–5 scales with notes; missing/unassessable dimensions are null, not zero. Editing effort, latency, preparation time, measured tokens and monetary costs stay separate from ratings.

Use the canonical paired summary; average reviewers within tasks and treat tasks, not individual ratings, as the experimental units. Report per-domain paired differences, failure/coverage rates, missing measurements and reviewer disagreement. The current evaluator provides descriptive summaries; it does not confer causal efficacy, guaranteed blinding or statistical significance. Any later inferential protocol belongs with the canonical evaluator owner before data inspection.

## Decision gates

Advance a domain only if reviewers find a practically useful relevance/editing benefit with no deterioration in fidelity or retained qualifications, and the result is supported across its registered task set rather than one showcase. Report task-specific failures and uncertainty. Customer adoption/willingness to pay requires separate actual user evidence. Software tests, source hashes and generated concept art cannot satisfy either gate.

## Participant and data safeguards

Participants receive a plain-language task and consent/data-use explanation before collection, can decline recording, and use only permissioned sources. The study owner must supply actual contacts, retention/deletion rules and approved handling for private organisational material. Development examples, public historical demonstrations and fictional game data do not count as held-out customer tasks. Tasks and participant details remain in a separate permissioned study workspace.

The prepared kit currently contains 150 reserved slots and zero completed held-out cases, participants or qualified reviewers. Structure validation is not execution approval. Recruit people and suitable work, confirm rights/independence and release readiness, then freeze and run through the canonical evaluator.

## Commercial and expert contribution boundaries

Record actual model, search, infrastructure and failed-attempt costs plus analyst editing/support time. Unknown costs remain missing, never zero. Cost-based quotes specify seats and included usage; the planning allowance does not promise an invoice cap. Transactional marketplace features and paid activation remain outside the current release.

Expert packs need a named maintainer, licensed primary sources, dates, review criteria, version history, revocation and corrections. Review verifies source support and applicability within a declared domain, rather than granting general authority to a model. Original author/upstream credit and a reproducible worked example accompany every accepted contribution.
